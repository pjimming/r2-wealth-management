# R2 Wealth Management

一套面向中国银行 R2/PR2 理财的操作型技能，用于把产品筛选、资金分配、买入核验、持仓替换和周期复盘连成一套可执行的决策流程。

它不追求找出单一“最高收益产品”，而是先确认产品能不能买、收益证据是否足够，再判断是否值得进入期限桶和具体仓位。

## 适合什么时候使用

- 有一笔资金要配置到 R2，需要从产品池生成期限桶和金额方案。
- 想比较某只产品的期限、收益、费率、流动性和交易规则。
- 已持有产品即将到期或开放赎回，需要判断继续持有、观察还是替换。
- 想建立目标收益、流动性、回撤和复盘纪律。
- 需要扫描招行 R2 产品池，或解释当前快照为何包含或排除某只产品。

不适合股票、基金、存款替代或保证收益类规划。

## 核心能力

### 产品研究池

先按 R2/PR2、人民币、公募、开放状态、期限和普通可买条件筛选，再按收益证据分层：

| 档位 | 可用数据 | 使用方式 |
|---|---|---|
| 完整 1Y | 3M/6M/1Y 完整；short 桶另使用 1M | 按期限桶评分和比较 |
| 缺 1Y | 3M/6M 完整 | 用可得周期计算参考年化 |
| 仅 3M | 只有 3M | 可评分，但标记证据较弱 |
| 仅 1M | 只有 1M | 只作新品观察，不自动配置；人工评估单只/合计不超过 5% |
| 无数据 | 没有有效收益周期 | 只展示，不推测收益 |

在招行工作区，缺 1Y 和仅 3M 的自动候选分别执行单只 10%、同类合计 20% 上限。仅 1M 的产品只进入观察，不自动配置；人工观察单只/同档合计不超过 5%。发行方只用于识别和展示，不作为仓位上限。

### 期限桶配置

默认采用全仓 R2。产品评分只认以下四个期限桶：

| 评分桶 | 期限 | 参考年化窗口 |
|---|---|---|
| 日开 `cash` | 恰好 0 天 | 1M 70% + 3M 30%；只展示 |
| 短期 `short` | 1–30 天 | 1M 20% + 3M 50% + 6M 30% |
| 中期 `medium` | 31–100 天 | 3M 50% + 6M 30% + 1Y 20% |
| 长期 `long` | 101 天以上 | 3M 20% + 6M 40% + 1Y 40% |

缺失窗口只在所属桶的剩余窗口内重新归一化；全部缺失时明确不可计算，不按 0 补齐。日开产品不评分、不排名、不分配；组合流动性由短期限桶承担，并优先选择 7–30 天或 T+1 可赎回产品。

配置模型：

| 模型 | 短 1–30 天 | 中 31–100 天 | 长 101 天+ | 适用场景 |
|---|---:|---:|---:|---|
| 保守型 | 45% | 40% | 15% | 近期可能用钱 |
| 均衡型 | 40% | 40% | 20% | 大多数稳定结余资金 |
| 收益型 | 30% | 40% | 30% | 能接受较长锁仓 |
| 哑铃型 | 50% | 0% | 50% | 兼顾流动性和长端收益 |
| 阶梯型 | 35% | 35% | 30% | 希望定期有资金到期 |
| 3% 进取型 | 30% | 35% | 35% | 目标型配置起点 |

3% 是组合目标，不是收益承诺。如果当前产品池和历史收益不支持，会明确显示缺口，不用杠杆或无关高风险产品补收益。

本 Skill 的 `total_score` 是稳定性、流动性、收益、费用和执行的多因子评分；应用中的 `selection_score` 是期限调整收益评分。两者可以共享同一个参考年化，但不是同一个排名指标。

### 买入与额度检查

买入前核对：

- 风险等级、产品类型和底层资产；
- 期限、最短持有期、买入和赎回截止时间；
- 确认日、到账日、赎回费和申购费；
- 起购金额、当日额度、份额类别和是否关门；
- 业绩基准与历史收益的统计口径。

公开数据和账户额度不能互相替代。最终交易仍由用户在银行 App 中完成。

### 持仓替换

对已确认持仓逐批比较同风险档、同期限桶候选，并计算：

- 当前参考年化和候选参考年化；
- `T+N` 赎回、到账和申购确认等待；
- 费用后的有效计息和切换成本；
- 盈亏平衡年化、预计多赚金额和期限变化；
- 基本面、流动性、价格资金和治理/融资失效条件。

输出结论分为“继续持有”“观察”“建议替换”。锁定期内不会把计划替换写成当前可执行动作。

### 周期复盘

跟踪账户收益、逐产品收益、目标差距、负收益天数、最大回撤、闲置资金拖累、费用和额度命中率。产品历史表现只作为观察证据，不把短样本直接外推为稳定年化。

## 怎么调用

在 Codex 中显式调用：

```text
$r2-wealth-management 帮我检查当前 R2 配置，并给出下周需要复核的事项。
```

常用请求：

```text
$r2-wealth-management 用 30 万做均衡型 R2 配置，先检查当前产品池能不能支持 2.5%。
```

```text
$r2-wealth-management 比较这两只 90 天产品，算上费率和赎回到账，值得切换吗？
```

```text
$r2-wealth-management 这只产品只有 3M 和 6M 收益，没有 1Y，应该怎么处理？
```

## 附带的计算工具

| 工具 | 作用 |
|---|---|
| `scripts/score_products.py` | 产品硬筛选、证据分层、多因子评分和期限调整参考年化 |
| `scripts/evidence.py` | 统一证据档位、期限桶、参考年化、应用兼容评分和短历史仓位规则 |
| `scripts/allocate.py` | 按短/中/长期限桶分配金额并检查单只、证据档和起购约束 |
| `scripts/switch_calc.py` | 按复利计算切换费用、等待期和盈亏平衡年化 |
| `scripts/review.py` | 计算收益、年化、回撤、目标差距和月度评级 |
| `scripts/verify_policy.py` | 用同一组黄金案例对照 Python Skill 与工作台 JS 收益内核 |

这些脚本只使用 Python 标准库，需要 Python 3.10+。示例产品池、日志和复盘模板位于 `assets/`。

跨实现验收：

```text
python -m unittest discover -s tests -v
python scripts/verify_policy.py --app-root D:\codex\钱多多财富工作台
```

## 典型输出

- 产品筛选表：证据档位、可用窗口、期限调整参考年化、风险、期限、费率和额度状态。
- 配置方案：短/中/长期限桶金额、单只金额、可用额度、未分配原因。
- 单品备忘录：产品画像、收益证据、流动性、费用、匹配度和持有/退出条件。
- 持仓复核：当前产品、候选产品、收益口径状态、切换成本、复利盈亏平衡和最终结论。
- 复盘摘要：实际收益、目标差距、回撤、流动性、费用和流程执行情况。

## 边界

- 只处理已确认属于 R2/PR2 的银行理财产品。
- 不登录银行账户，不读取或保存密码、验证码和证件信息。
- 不查询实时额度，不代替用户下单、赎回或转账。
- 不把历史收益、成立以来年化或短期冲高数据当成未来收益。
- 不承诺保本、固定收益或一定达到 3% 目标。
- 真实账户数据只用于用户授权的本地分析，不应提交到公开仓库。
