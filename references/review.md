# 复盘：每天一分钟，每月十分钟，每季三十分钟

复盘的目的是验证“流程有没有被执行”，不是给每天的涨跌找解释。R2 产品的日收益噪音很大，单日高低不代表策略好坏。

## 每日记录

最小字段：

| 字段 | 说明 |
|---|---|
| `date` | 日期，YYYY-MM-DD |
| `principal` | 当日 R2 总本金 |
| `daily_pnl` | 当日收益，亏损用负数 |
| `cash_balance` | 其中日开/现金管理余额；当前工作区新增目标固定 0%，已有日开只作迁移事实 |
| `action` | 无操作/买入/赎回/切换 |
| `notes` | 额度、到账、异常、情绪 |

模板见 `assets/daily_log_template.csv`。

全仓 R2 模式：通常 `cash_balance` 填 0。若账本仍有历史日开持仓，按真实余额填写并标记“迁移事实”，但不把新增日开当作目标。不要把组合外的活期/存款计入 `principal` 或 `cash_balance`，否则现金拖累会失真。

一分钟版：

1. 今天有没有操作？没有就写“无操作”。
2. 当日收益、月累计是多少？
3. 短桶（1–30 天，优先 7–30 天或 T+1 可赎回）够不够下一次用钱？
4. 有没有规则变化或异常？

不要把“今天万 8”当成加仓理由，也不要把“今天挂 0”当成赎回理由。

## 每周检查

- 本周收益、月累计、年累计；
- 连续负收益天数；
- 是否有产品明显偏离同期限基准；
- 是否有费率、经理、底层、赎回规则变化；
- 额度是否按计划命中，未命中的原因；
- 日开新增目标是否仍为 0%；短桶是否低于 30%；
- 单只是否超过 25–30%；发行方名称、金额和占比只记录展示，不判超限。

## 月度复盘

### 指标

| 指标 | 计算 | 看什么 |
|---|---|---|
| 月收益 | 当月 `daily_pnl` 合计 | 绝对金额 |
| 月收益率 | 月收益 ÷ 月均本金 | 与自己的目标比 |
| 年化收益率 | `(1+区间收益率)^(365/天数)-1` | 仅作参考，短期年化噪音大 |
| 最大回撤 | 累计收益曲线的峰谷最大跌幅 | 持有体验 |
| 负收益天数占比 | 负收益天数 ÷ 交易记录天数 | 稳定性 |
| 最好/最差单日 | 最大/最小 `daily_pnl` | 是否异常 |
| 闲置资金拖累 | 平均日开/未归类余额 ÷ 平均本金 | 是否太多钱没工作；新增日开目标应为 0 |
| 费用拖累 | 当月费用 ÷ 平均本金 | 是否被费率吃掉 |
| 额度命中率 | 成功买入次数 ÷ 计划买入次数 | 执行效率 |
| 集中度 | 单只/期限桶占比 | 是否偏离单只与期限桶规则；发行方占比只展示 |
| 操作次数 | 买入+赎回+切换次数 | 是否过度交易 |

### 3% 目标跟踪

- 目标年化：3%；
- 月目标：约 0.247%（复利）或 0.25%（单利粗算）；
- 目标缺口：`目标年化 − 期限调整参考年化`；同时展示可用窗口、状态和原因；
- cash/short 可使用桶指定的 1M，medium/long 不使用 1M；缺 1Y 或仅 3M 时标出 10%/20% 上限，仅 1M 新品标出 5%/5% 人工观察上限；
- 连续 3 个月期限调整参考年化 <3%，检查久期、信用、费率、额度，判断目标是否适合当前 R2 池；
- 为了追 3% 导致回撤/流动性超限时，优先降风险，不用杠杆补收益。

### 月度评级

公开笔记里用过一套月度收益率评级，可作为个人参考：

| 月收益率 | 评级 |
|---|---|
| <0.16% | 不及格 |
| 0.16%–0.20% | 及格 |
| 0.20%–0.25% | 良好 |
| 0.25%–0.30% | 优秀 |
| ≥0.30% | 卓越 |

这不是行业标准，也不是收益承诺。它只适合作为“低风险 R2 组合”的自我对照；短历史或未分配资金比例高、产品期限短时，收益率自然会低一些。评级要和闲置资金拖累、回撤、流动性一起看。

不满 28 个自然日或记录少于 20 条的月份，脚本标记为“样本不足”，不参与评级。短样本的年化数字只作参考。

### 每月五问

1. 这个月有没有按计划执行？哪一次偏离了，为什么？
2. 哪笔操作真正增加了收益，哪笔只是增加了忙碌？
3. 闲置资金拖累是否接近 0？各期限桶的期限调整参考年化离 3% 差多少？
4. 有没有产品触发风险、流动性或费率红线？
5. 下个月只改一件事，改什么？

## 决策日志

每次买入、赎回、切换都记一条：

`日期 | 产品 | 动作 | 当时的理由 | 预期（收益/流动性/风险） | 实际结果 | 事后评价`

事后评价只分三类：

- **流程正确，结果好**：继续；
- **流程正确，结果差**：可接受，别因一次结果改规则；
- **流程错误，结果好**：最危险，必须记录并纠正。

## 季度复盘

三十分钟，回答六个问题：

1. 短/中/长三个工作桶的比例偏离目标多少？超过 5 个百分点了吗？
2. 单只和期限桶是否仍符合规则？发行方占比只作持仓状态记录。
3. 期限阶梯是否还能覆盖未来 12 个月现金流？
4. 费用和闲置资金拖累是否在可接受范围？
5. 有没有产品需要替换（规则变化、持续跑输、流动性变差）？
6. 这套方法花的时间，和超额收益相比是否值得？

## 用脚本复盘

准备 CSV：

```csv
date,principal,daily_pnl,cash_balance,action,notes
2026-09-01,540000,52,0,无操作,全仓R2
2026-09-02,540000,61,0,无操作,
```

运行：

```bash
python scripts/review.py --input assets/daily_log_template.csv --target 3.0 --format markdown
```

脚本会输出总收益、区间收益率、年化、目标差距、最大回撤、负收益天数、闲置资金拖累和月度评级。它不会判断产品好坏，也不会给买卖建议。

## 复盘时不要做

- 用单日收益证明策略对错；
- 把年化收益按一个月简单乘 12；
- 只看收益率，不看回撤、闲置资金拖累和费用；
- 因为一次“抢到高收益”就加大风险；
- 因为一次“挂 0”就全部赎回；
- 把“额度命中率”当成唯一 KPI，忽略产品质量。
